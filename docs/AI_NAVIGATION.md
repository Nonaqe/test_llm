# Навигация для ИИ-агентов

## Краткое содержание

Алгоритм поиска, маршруты по задачам, правила «что не читать». Документ процедурный, не содержательный.

## 1. Как искать информацию (алгоритм)

1. Прочитать `INDEX.md` — ограничения проекта и таблицу разделов.
2. Определить тип задачи и открыть **1–3 раздела** из маршрутов (раздел 4) или выбрать по `when_to_read` из `documentation.manifest.json`.
3. Прочитать **паспорт** каждого выбранного файла (блок между `---` в начале). Если `when_not_to_read` совпадает с вашей задачей — файл закрыть.
4. Только после этого читать контент файла. Искать по `keywords` внутри больших файлов.
5. Перейти по `related` паспорта, если контекста не хватает.

## 2. Что читать первым делом

Всегда в этом порядке:

1. `INDEX.md` (ограничения проекта — обязательный контекст).
2. Этот файл.
3. Разделы маршрута вашей задачи (раздел 4 ниже).

Для любой задачи, затрагивающей архитектуру: `03_SYSTEM_ARCHITECTURE.md` (DOC-003) — перед профильными разделами.

## 3. Как НЕ читать всю документацию (анти-паттерны)

Запрещено:

- Читать файлы подряд по номерам (01→02→…).
- Открывать документы со статусом `planned` в манифесте — их не существует; **выдумывать их содержимое нельзя**.
- Догадываться о содержимом по имени файла вместо чтения паспорта.
- Копировать факты из одного раздела в другой вместо ссылки (нарушение «единственного источника истины»).
- Читать гайды (DOC-021…024) при задачах разработки — и наоборот, читать внутренние документы (DOC-005…020) при пользовательских вопросах.

## 5. Единственный источник истины

Каждый факт проекта описан ровно в одном документе; остальные ссылаются на него. Перед изменением любого факта — править документ-источник (таблица в `INDEX.md`). Следствия:

- Расхождение между документами = бага документации: правится документ-источник, а не копия.
- Внутренние детали (схема БД, контракты API) не пересказываются в обзорных документах — только ссылки.

## 6. Как читать паспорта

Поля паспорта каждого файла:

- `when_to_read` — сигнатура задач, при которых файл нужен.
- `when_not_to_read` — сигнатура задач, при которых файл пропускается.
- `keywords` — термины для быстрого поиска внутри файла.
- `related` — смежные разделы для догрузки контекста.
- `status` — `planned` (файла нет), `draft` (черновик, возможны пробелы/TBD), `review`, `approved`.

## 7. Приоритеты при ограниченном контексте

Если контекст ограничен, читать только документы с `priority: high`, начиная с DOC-003 (архитектура) и профильного раздела задачи. Гайды (DOC-021…024), FAQ (DOC-027), глоссарий (DOC-028) — по прямой необходимости.
