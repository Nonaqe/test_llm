## 2. Главные цели продукта

**Цель №1 — максимально простое подключение.**

```text
WordPress:   Install Plugin → Configure → Enable
Чистый сайт: Copy Script → Paste Script → Done
```

**Цель №2 — максимально простая настройка AI.** Администратор без программирования: настраивает компанию и стиль AI, загружает документы, добавляет FAQ/услуги/цены, задаёт правила, определяет правила передачи оператору.

## 3. Целевые ниши (ниша задаётся настройками, не кодом)

| Ниша | Что знает AI |
|---|---|
| Интернет-магазин | товары, цены, наличие, доставка, возврат, оплата |
| Юридическая компания | услуги, практики, документы, цены, процесс работы |
| Клиника | услуги, врачи, цены, расписание, правила записи |
| Автосервис | услуги, автомобили, ремонт, цены, запчасти |

Требование: продукт **не привязывается к конкретной нише**; пресеты ниш — только преднастроенные шаблоны ассистента (V2).

## 5. Нефункциональные требования

| ID | Требование | Целевое значение MVP |
|----|------------|----------------------|
| NFR-1 | Автономность | Полная работа при недоступности инфраструктуры вендора |
| NFR-2 | Простота установки backend | Один VPS + Docker, ≤ 30 минут |
| NFR-3 | Простота подключения виджета | ≤ 5 минут на любом сайте |
| NFR-4 | Изоляция виджета | Виджет не ломает CSS/JS сайта и наоборот |
| NFR-5 | Размер виджета | ≤ 60 КБ gzip loader, тяжёлое — лениво |
| NFR-6 | Латентность первого токена AI | ≤ 3 с (P95) при типичном RAG-контексте |
| NFR-7 | Масштаб одной установки | ~10–50 одновременных диалогов, ~1 млн чанков на проект |
| NFR-8 | Безопасность данных | Данные и ключи у заказчика; секреты шифруются |
| NFR-9 | Заменяемость AI-провайдера | Через интерфейс провайдера, без изменения ядра |
| NFR-10 | Расширяемость платформ | Новая платформа = integration-слой, ядро не меняется |

## 6. Рамки MVP

**Входит (кратко; полный список — DOC-025):** self-hosted Docker Compose установка с installer'ом и визардом; backend (REST + realtime); admin panel; виджет; generic JS интеграция; WordPress-плагин; AI с provider-abstraction; Knowledge Base; RAG; операторы и handoff; аутентификация и RBAC; базовая аналитика; бэкапы.

**Не входит (вынесено в V2/V3):** дополнительные нативные AI-провайдеры; reranker; вебхуки и API-keys; вложения файлов в чат; canned replies; iframe-режим виджета; 2FA; новые платформы (Laravel/React/Vue/Next/Shopify); каналы (Telegram/WhatsApp); CRM; HA-кластер.

## Частые ошибки

- Добавлять в MVP «просто ещё одного провайдера/платформу» — ломает цель качества двух главных сценариев; всё новое — через DOC-025.
- Вводить обязательную зависимость от внешнего сервиса (нарушение NFR-1) — внешнее допустимо только опционально (телеметрия opt-in, удалённый бэкап).
