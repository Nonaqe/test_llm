# Универсальная web-интеграция

## Краткое содержание

- Механизм подключения (одна строка).
- Откуда берётся сниппет.
- SDK и SPA.
- Origin allowlist и злоупотребление ключом.
- Adblock-устойчивость.
- Добавление новой платформы (путь без правки ядра).

## 1. Механизм подключения

```html
<script
  src="https://chat.customer-domain.com/widget.js"
  data-chat-key="pk_live_9f3a..."
  defer
></script>
```

Свойства механизма:

- Скрипт сам выводит все URL (API, Socket.IO) из собственного `src` — никаких других настроек.
- Ключ **публичный** (publishable): его видно в HTML — это нормально, его полномочия ограничены (раздел 4).
- Работает на любом хостинге, включая shared: сайт лишь отдаёт HTML со `<script>`, весь чат живёт на сервере заказчика (DOC-003).

Куда вставлять: перед `</body>` (или в head с `defer`). На PHP-сайтах — в общий футер/шаблон.

## 2. Откуда берётся сниппет

Админка чата → Сайты → нужный сайт → «Сниппет для установки»: готовый `<script>` с уже подставленным ключом и доменом сервера (копировать → вставить → готово). Там же — регенерация ключа и список разрешённых доменов.

## 3. SDK (программное подключение)

Для SPA и динамических страниц — `ChatWidget.init()` вместо data-атрибута; полный API — DOC-008 §3.

Пример для React (для Vue/Next аналогично):

```jsx
import { useEffect } from "react";

export function ChatMount() {
  useEffect(() => {
    const s = document.createElement("script");
    s.src = "https://chat.customer-domain.com/widget.js";
    s.defer = true;
    document.body.appendChild(s);
    return () => s.remove();          // при размонтировании
  }, []);
  return null;
}

// программное управление после загрузки:
// window.ChatWidget?.open()
```

Официально в MVP поддерживается только generic web (script/SDK); React/Vue-обёртки — V3 через тот же Public Widget API (DOC-003 §5).

## 4. Origin allowlist и защита ключа

- У каждого сайта в админке — список разрешённых origins (`sites.allowed_origins`).
- `POST /widget/v1/init` проверяет заголовок Origin: чужой домен → `403 INVALID_ORIGIN`.
- Утекающий ключ даёт злоумышленнику лишь возможность «слать сообщения от имени посетителей» с чужого домена — но origin-проверка его отсечёт; прямой API-доступ ограничен rate limit (DOC-007 §6).
- Компрометация → кнопка «Регенерировать ключ» в админке (старый ключ отзывается мгновенно).

Полной защиты от «украду ключ и подделаю Origin» в браузере не существует по природе платформы; компенсации: origin-проверка + rate limit + регенерация. Секретные операции доступны только приватной зоне `/api/v1` (DOC-015).

## 5. Adblock-устойчивость

Скрипт отдаётся с **собственного домена заказчика** (`chat.customer-domain.com`), а не с домена вендора — в стандартные блок-листы ESL-типа не попадает. Это преимущество self-hosted модели.

## 6. Добавление новой платформы (путь)

Новая платформа (Laravel, Shopify, другая CMS) добавляется **новым integration-пакетом, без правки ядра** (ADR-007, NFR-10):

1. Выбрать контракт из Integration Contract (DOC-003 §5):
   - может вставить `<script>` → достаточно Widget Bootstrap (ничего разрабатывать не нужно);
   - нужен нативный UI платформы → Public Widget API v1;
   - нужна серверная интеграция → Admin API v1 (+ webhooks в V2).
2. Создать пакет `integrations/<платформа>/` по правилам DOC-004.
3. Написать документ-инструкцию по образцу DOC-009/DOC-024.
4. Ядро и релизы chat-сервера не затрагиваются.

Пустые адаптеры заранее не создаются (принцип MVP — DOC-002 §6).

## Чек-лист подключения сайта

- [ ] Сайт создан в админке чата, ключ скопирован.
- [ ] Домен сайта добавлен в allowed_origins.
- [ ] Сниппет вставлен перед `</body>` (или SDK-init в SPA).
- [ ] Проверка: страница → кнопка чата → тестовое сообщение → ответ AI.
- [ ] Проверен мобильный вид.

## Частые ошибки

- **Локальная разработка без добавления origin** (`http://localhost:3000`) — добавить в allowlist на время разработки.
- **Вставка сниппета разных сайтов на одну страницу** — не поддерживается в MVP (один виджет на страницу).
- **Ключ в query-string вместо data-атрибута** — только `data-chat-key`.
- **Копирование сниппета с чужого сайта** — ключ привязан к сайту/origins, будет `INVALID_ORIGIN`.
