# Руководство интегратора

## Краткое содержание

- Что нужно до начала.
- Сценарий: чистый HTML/PHP сайт.
- Сценарий: WordPress.
- Сценарий: SPA.
- Проверка установки.
- Диагностика embed.
- Добавление новой CMS.

## 1. До начала

От администратора чата (DOC-022) получите: **URL чат-сервера** (`https://chat.example.com`) и **сниппет с публичным ключом** сайта. Убедитесь, что домен клиента добавлен в allowed origins.

## 2. Сценарий: чистый HTML/PHP сайт

1. Откройте общий шаблон страниц (обычно `footer.php` / общий include футера).
2. Вставьте перед `</body>`:

```html
<script
  src="https://chat.example.com/widget.js"
  data-chat-key="pk_live_9f3a..."
  defer
></script>
```

3. Сохраните, опубликуйте. Готово — правка одного файла.
4. Проверка — раздел 5.

Подгонка под дизайн сайта — вручную (уровни кастомизации в DOC-008 §4): CSS-переменные на сайте или «Свой CSS» в конструкторе.

## 3. Сценарий: WordPress

1. WP Admin → Plugins → Add New → Upload Plugin → `uni-chat.zip` → Activate.
2. Меню «Universal Chat» → Settings:
   - Chat Server URL: `https://chat.example.com`
   - Public Chat Key: `pk_live_9f3a...`
   - Где показывать: все страницы (или выбранные).
3. «Проверить соединение» — должен позеленеть health.
4. Сохранить. Кнопка чата появляется в футере сайта.

Детали и multisite — DOC-009. Правка темы не требуется.

## 4. Сценарий: SPA (React и подобные)

Компонент монтирования виджета (полный пример — DOC-010 §3):

```jsx
useEffect(() => {
  const s = document.createElement("script");
  s.src = "https://chat.example.com/widget.js";
  s.defer = true;
  document.body.appendChild(s);
  return () => s.remove();
}, []);
```

Для программного открытия: `window.ChatWidget?.open()` после загрузки скрипта. Один виджет на страницу.

## 5. Проверка установки

| Шаг | Ожидание |
|---|---|
| Открыть страницу сайта | В углу — кнопка чата (цвет/позиция из настроек) |
| Клик → панель | Приветствие; на мобиле — полноэкранно |
| Тестовое сообщение | Ответ AI со стримингом |
| «Позовите оператора» | Диалог появляется в очереди оператора |
| DevTools → Console | Нет ошибок; WS connected (или polling fallback) |
| `GET /widget/v1/health` | `200` |

## 6. Диагностика embed

| Симптом | Причина | Действие |
|---|---|---|
| Кнопки нет | Сниппет не вставлен/не опубликован; WP-плагин выключен | Проверить исходный HTML страницы (`Ctrl+U`) на `<script ...widget.js` |
| `403 INVALID_ORIGIN` | Домен не в allowed origins | Администратор добавляет домен (DOC-022 §2) |
| `404` на widget.js | Неверный URL сервера в сниппете | Сверить с URL из админки |
| Чат есть, AI молчит | Провайдер/ключ на сервере | Страница диагностики (DOC-019); сообщить админу |
| WS не подключается | Прокси/CDN режет upgrade | Виджет сам перейдёт на fallback; при необходимости — конфиг прокси |
| Кривые стили | Агрессивный CSS сайта | CSS-переменные/custom_css (DOC-008 §4); крайний случай — V2 iframe-режим |

## 7. Добавление новой CMS

Если платформа умеет вставить `<script>` — используйте сниппет как есть (раздел 2). Нужен нативный UI или серверная интеграция — Integration Contract (DOC-003 §5, DOC-010 §6): разрабатывается пакет интеграции без правки ядра.

## Чек-лист подключения

- [ ] Сниппет/плагин установлен; health зелёный.
- [ ] Origin добавлен; проверен тест-диалог и эскалация.
- [ ] Мобильный вид проверен.
- [ ] Дизайн согласован (уровень кастомизации зафиксирован).
