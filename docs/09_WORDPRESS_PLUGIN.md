# WordPress-плагин

## Краткое содержание

- Назначение и принцип «тонкого слоя».
- Установка и настройка.
- Вставка виджета, шорткод.
- Права, безопасность, multisite.
- Обновление и отладка.

Минимальные версии: WordPress 6.0+, PHP 7.4+ (ASSUMPTION, TBD — см. DOC-002 Q-5).

## 1. Назначение

Плагин — **только интеграционный слой**: настройки + вставка того же `widget.js`. Ни одной строчки бизнес-логики, никакого дублирования backend'а, никаких вызовов AI и хранения диалогов в БД WordPress (одна опция настроек). Вся логика — на chat-сервере заказчика (DOC-003, ADR-007).

Установка не требует правки темы, PHP-файлов или JavaScript: вставка через хук `wp_footer`.

## 2. Структура файлов

```text
integrations/wordpress/uni-chat/
├── uni-chat.php           # регистрация, хуки, активация/деактивация
├── includes/
│   ├── settings.php       # страница настроек (нативный WP UI)
│   └── embed.php          # вставка <script> с ключом
├── assets/
│   └── admin.css          # стили страницы настроек (только для админки)
└── readme.txt             # для каталога wp.org
```

## 3. Установка

```text
WP Admin → Plugins → Add New
  → Upload Plugin → uni-chat.zip → Install Now → Activate
  → меню «Universal Chat» → Settings
```

(Либо установка из каталога wp.org поиском — после публикации, TBD.)

## 4. Настройки

| Поле | Описание |
|---|---|
| Chat Server URL | Адрес чат-сервера, например `https://chat.customer-domain.com` |
| Public Chat Key | Публичный ключ сайта из админки чата (`pk_live_...`) |
| Включён | Вкл/выкл чат на сайте |
| Где показывать | Все страницы / выбранные (по ID/шаблону) |
| Не загружать до согласия cookie | Интеграция с WP Consent API (см. 4.3) |

Ключ и URL скопированы из визарда админки чата (DOC-022). Секретов в плагине нет — только publishable key.

### 4.1 Health check

Кнопка «Проверить соединение» → плагин вызывает `GET {server}/widget/v1/health` и показывает статус и версию сервера. Диагностика на первой линии — без консоли браузера.

### 4.2 Вставка виджета

`embed.php` (принцип):

```php
add_action( 'wp_footer', function () {
    $server = get_option( 'unichat_server_url' );
    $key    = get_option( 'unichat_public_key' );
    if ( ! unichat_is_enabled_for_current_page() ) {
        return;
    }
    printf(
        '<script src="%s/widget.js" data-chat-key="%s" defer></script>',
        esc_url( $server ),
        esc_attr( $key )
    );
} );
```

Тот же скрипт и тот же механизм, что и на чистом сайте (DOC-010) — единый Integration Contract.

### 4.3 Consent (cookie/GDPR)

Если включена опция — скрипт вставляется только после события согласия WP Consent API; совместимо с популярными consent-плагинами. Без согласия виджет не грузится вовсе (никаких запросов).

### 4.4 Шорткод

`[uni_chat]` на конкретной странице — рендерит контейнер и принудительно вставляет виджет на этой странице (например, страница «Поддержка»), независимо от правила «где показывать».

## 5. Права доступа

- Настройки плагина: capability `manage_options` (администратор WP).
- Плагин не создаёт ролей, таблиц и пользователей; виджет работает от анонимного посетителя (visitor token — DOC-015).

## 6. Multisite

Network-активация: настройки у каждого подсайта свои (per-site опции), у каждого — свой ключ (свой сайт в чат-платформе).

## 7. Безопасность

- Вывод URL/ключа через `esc_url`/`esc_attr`; формы настроек — nonce + `current_user_can`.
- Плагин ничего не принимает от посетителя (вся связь виджет ↔ сервер напрямую).
- Никаких исходящих вызовов, кроме health check на настроенный сервер. Phone-home отсутствует.

## 8. Обновление

Обновляется штатно: каталог wp.org (после публикации, TBD) или загрузкой нового ZIP. Цикл релизов плагина независим от релизов chat-сервера (обратная совместимость по Integration Contract — DOC-007 §7).

## 9. Отладка

| Симптом | Причина | Действие |
|---|---|---|
| Кнопка чата не появляется | Плагин выключен / страница исключена / не настроен ключ | Проверить настройки и «где показывать» |
| Health check красный | Неверный URL или сервер недоступен | Проверить URL, `https://`, доступность сервера |
| `INVALID_ORIGIN` в консоли | Домен сайта не в allowlist сайта в админке чата | Добавить домен в allowed_origins (DOC-022) |
| Скрипт грузится, чат молчит | Скрыт consent-опцией | Проверить интеграцию consent |
| Конфликт с темой/плагином | Агрессивный CSS/JS темы | Уровни кастомизации DOC-008 §4; в V2 — iframe-режим |

## Чек-лист релиза плагина

- [ ] Нет бизнес-логики и обращений к чужим таблицам WP.
- [ ] Вывод экранирован; формы с nonce и capability.
- [ ] Health check работает на свежей установке.
- [ ] Протестировано: обычный сайт, multisite, consent-режим.

## Частые ошибки

- **Перенос логики в плагин** «для простоты» — нарушение ADR-007; всё в Core.
- **Вставка скрипта в `header`** — только `wp_footer` (скорость страницы).
- **Хранение секретных ключей в плагине** — их не существует; publishable key не секрет.
