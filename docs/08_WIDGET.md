# Чат-виджет

## Краткое содержание

- Технология и изоляция.
- Подключение и SDK.
- Жизненный цикл.
- **Кастомизация дизайна: три уровня.**
- Стриминг, идентичность посетителя, мобайл, деградация.
- Сборка и бюджет размера.

## 1. Технология

**Web Component (custom element `<uni-chat-widget>`) + Shadow DOM, рендер на Preact (~4 КБ).** Один ESM-файл `widget.js` ≤ 60 КБ gzip (loader); тяжёлые части (markdown-рендер стрима) подгружаются лениво при первом открытии панели.

Почему не iframe и не обычный bundle — ADR-004 (DOC-026): Shadow DOM даёт CSS-изоляцию, сопоставимую с iframe, при нативной адаптивности и без postMessage-обвязки; обычный bundle ломал бы сайты (нарушение NFR-4).

## 2. Изоляция от сайта

- Всё дерево UI — внутри shadow root; стили — через adopted stylesheets; собственный CSS-reset внутри.
- Global namespace страницы не загрязняется (единственный экспорт — объект `ChatWidget`).
- z-index виджета управляется и-doc'ом; виджет не полагается на глобальные скрипты/библиотеки сайта.
- **Единственная контролируемая «дырка»** — CSS custom properties `--uni-chat-*`, которые намеренно наследуются сквозь границу shadow DOM (для ручной темизации, раздел 4).

## 3. Подключение и SDK

Декларативное (любой сайт):

```html
<script
  src="https://chat.customer-domain.com/widget.js"
  data-chat-key="pk_live_9f3a..."
  defer
></script>
```

Скрипт сам выводит все URL из собственного `src` — конфигурация не нужна. `data-chat-key` — публичный (publishable) ключ сайта.

Программное (SPA, динамическая инициализация):

```javascript
ChatWidget.init({ key: "pk_live_9f3a..." });   // единственный обязательный метод
ChatWidget.open();                              // открыть панель
ChatWidget.close();
ChatWidget.toggle();
ChatWidget.identify({ name: "Иван", email: "ivan@example.com" }); // опционально
ChatWidget.on("message", (msg) => console.log(msg.seq));
ChatWidget.setLocale("en");
ChatWidget.destroy();                           // полное удаление из DOM
```

## 4. Кастомизация дизайна (три уровня, только ручная — автоподхвата дизайна сайта нет)

### Уровень 1 — конструктор в админке (без кода)

Настройки сайта → виджет: акцентный цвет, логотип, положение (право/лево), радиусы, приветствие, тексты интерфейса, язык, готовые темы. Хранится в `sites.widget_config` (jsonb). Покрывает большинство сайтов.

### Уровень 2 — ручная доводка CSS

**(a) CSS-переменные** — верстальщик сайта переопределяет их в своём CSS; они пробрасываются сквозь Shadow DOM:

```css
:root {
  --uni-chat-accent: #b8860b;
  --uni-chat-font-family: "Montserrat", sans-serif;
  --uni-chat-radius: 4px;
}
```

Справочник переменных (начальный состав; расширяется — обновлять здесь):

| Переменная | Назначение | Дефолт |
|---|---|---|
| `--uni-chat-accent` | Акцентный цвет (кнопка, ссылки, отправка) | `#4f46e5` |
| `--uni-chat-accent-contrast` | Текст на акценте | `#ffffff` |
| `--uni-chat-bg` | Фон панели | `#ffffff` |
| `--uni-chat-fg` | Основной текст | `#111827` |
| `--uni-chat-bubble-visitor` | Фон сообщения посетителя | акцент |
| `--uni-chat-bubble-ai` | Фон ответа | `#f3f4f6` |
| `--uni-chat-radius` | Радиусы углов | `12px` |
| `--uni-chat-font-family` | Шрифт | системный стек |
| `--uni-chat-font-size` | Базовый кегль | `15px` |
| `--uni-chat-position-bottom` | Отступ кнопки от низа | `20px` |
| `--uni-chat-z-index` | Слой виджета | `2147483000` |

**(b) Поле «Свой CSS» в конструкторе** (`widget_config.custom_css`): произвольные стили из админки, инжектируются внутрь shadow root. Валидация: только CSS (запрет `expression`, `url(javascript:)`, `@import`), лимит размера (10 КБ). Позволяет довести виджет до пиксельного соответствия без доступа к коду сайта.

### Уровень 3 — полностью свой интерфейс

Наш `widget.js` не используется: разработчик пишет собственный UI любой сложности на **Public Widget API v1** (`/widget/v1` + события Socket.IO, DOC-007). На этом же контракте строятся будущие официальные React/Vue-компоненты (V3).

### Что не настраивается на уровнях 1–2

Логика поведения и структура рендера сообщений (санитизация markdown, стриминг, цитаты) — фиксированы: произвольная правка ломает XSS-защиту и поддержку. Нужна полная свобода — уровень 3.

## 5. Жизненный цикл

```text
<script> загружен (defer)
  → авто-init по data-chat-key (или ручной ChatWidget.init)
  → POST /widget/v1/init {key, origin}        → visitor token + widget config
  → рендер лаунчера (кнопка)                  ← конфиг: цвет/позиция/лого/тексты
  → клик → ленивая загрузка панели
  → первое сообщение → POST /conversations     → диалог создан (state=AI_ACTIVE)
  → ответы: Socket.IO ai_token → message
```

Visitor identity: анонимный `anon_id` в `localStorage` домена сайта → диалог переживает перезагрузку и переходы по страницам; `identify()` дополняет профиль (имя/email — видны оператору).

## 6. Стриминг и рендер

- Токены `ai_token` рендерятся инкрементально (markdown), тяжёлый рендер-модуль грузится при первом открытии.
- **Весь HTML проходит DOMPurify** (allowlist) — и markdown ответов AI, и любой контент (DOC-015).
- Ссылки: `rel="noopener nofollow"`, протокол-allowlist (http/https/mailto).

## 7. Мобильная адаптация

- Узкие экраны: панель разворачивается на весь экран, safe-area-insets учитываются.
- Ввод не перекрывается клавиатурой (visualViewport).
- Лаунчер не перекрывает критические элементы (настраиваемый отступ).

## 8. Деградация связи

| Состояние | Поведение |
|---|---|
| WebSocket доступен | Норма: пуш `message`/`ai_token` |
| WS не поднимается | Socket.IO сам уходит в long-polling fallback |
| Полная потеря связи | REST-режим: отправка через POST + опрос `?after_seq=` с бэкоффом |
| Reconnect | Автоповтор + кэтч-ап пропущенных по seq (DOC-007 §4.3) |

## 9. Сборка и бюджет

- Vite → один ESM-файл; сборка падает в CI при превышении **60 КБ gzip** (NFR-5).
- Кэширование: `widget.js` — `max-age=300` (быстрые исправления), ленивые модули — immutable по хэшу.
- Зависимости виджета — только `@uni-chat/shared` (типы); React-семейство запрещено (DOC-004 §4).

## Чек-лист изменения виджета

- [ ] Размер бандла ≤ 60 КБ gzip (CI)?
- [ ] Новый визуальный параметр → CSS-переменная + строка в таблице раздела 4?
- [ ] Новый пользовательский текст → widget_texts (i18n), не хардкод?
- [ ] Рендер HTML идёт только через санитайзер?
- [ ] Проверено на мобильном профиле и при заблокированном WS?

## Частые ошибки

- **Стили сайта «не работают» внутри чата** — так задумано (изоляция); используйте CSS-переменные или custom_css.
- **Кастомизация правкой widget.js** — потеряется при обновлении; только уровни 1–3.
- **Ожидание ответа AI в POST /messages** — ответ приходит по Socket.IO (DOC-007).
- **Кэширование виджета навсегда** — обновления не доедут; только короткий max-age для `widget.js`.
- **Отсутствие origin в allowlist** — `INVALID_ORIGIN` при init; добавить домен в настройках сайта.
