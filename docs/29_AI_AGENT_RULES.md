# Правила для ИИ-агентов

## Краткое содержание

- Правила чтения.
- Правила изменения.
- Формат паспорта и стиля.
- Манифест и keywords.
- Связность документов.
- Источники истины.
- Устаревшее и маркеры.
- Создание новых разделов.
- Ответы на вопросы людей.

## 1. Правила чтения

1. Начинать с `INDEX.md`, затем `AI_NAVIGATION.md`; маршруты — по типу задачи.
2. Читать 1–3 релевантных раздела, не всё подряд; паспорта — до контента.
3. Файлы со статусом `planned` не существуют — не читать, не ссылаться на их содержимое, не выдумывать его.
4. Незнакомый термин → DOC-028, затем вернуться.

## 2. Правила изменения

1. **Изменять факт — только в документе-источнике** (таблица в INDEX.md). Прочие документы ссылаются, а не копируют.
2. Перед правкой прочитать целевой раздел целиком и его `related`.
3. Правка согласована с реальностью кода/системы; если код ещё не реализован — документ остаётся спецификацией, а не описанием факта (помечать статусом `draft`).
4. Обновить затронутые связанные документы (например, меняется API → DOC-007 и упоминания в DOC-008/010).
5. Нельзя: описывать SaaS как основную модель; предполагать обязательный внешний сервер вендора; игнорировать WordPress и generic web как основные интеграции; описывать shared hosting как поддерживаемый для backend.

## 3. Формат паспорта и стиль

Каждый документ начинается паспортом (YAML-блок между `---`):

```yaml
id: DOC-NNN                 # уникальный, не переиспользуется
title: Название
project: Universal Chat — Self-Hosted AI Chat Platform
version: 0.1.0              # версия документа
status: draft               # draft | review | approved
audience: developer, ...    # из списка: developer|architect|integrator|admin|operator|ai-agent
priority: high              # high | medium | low
summary: 2–4 предложения
when_to_read: ...
when_not_to_read: ...
keywords: через запятую
related:
  - DOC-XXX
```

После паспорта: краткое содержание → основной контент → чек-лист (если применимо) → частые ошибки (если применимо) → связанные разделы.

Стиль: технический, конкретный, без воды и маркетинга; таблицы, списки, блоки кода; явные заголовки; перекрёстные ссылки по ID (`DOC-NNN`). Русский язык; устоявшиеся английские термины допустимы (см. DOC-028).

## 4. Манифест и keywords

- При создании/изменении документа обновить `documentation.manifest.json` (все поля записи, `last_updated`).
- `keywords` — термины, по которым раздел ищут (включая синонимы из DOC-028); 3–8 штук.
- Манифест должен точно отражать существование файлов: `planned` до создания, `draft/review/approved` после.

## 5. Связность

- `related` паспорта — двусторонние: добавляя ссылку A→B, проверить обратную B→A (если уместно).
- Ссылки на разделы внутри текста — по ID + имени файла (`DOC-007`, `07_API.md`), не «см. выше/ниже».
- Новые домены знаний → проверить, нет ли уже источника истины (INDEX); дублирование запрещено.

## 6. Источники истины

Таблица — в `INDEX.md` (раздел «Таблица "источник истины"»). При расхождении документов: править источник, копию — заменить ссылкой. Архитектурные «почему» — только DOC-026 (ADR).

## 7. Устаревшее и маркеры

- Подтверждённо устаревший фрагмент не удаляется молча: помечать `NEEDS REVIEW` и описывать причину; устаревший документ целиком — статус `superseded` + замена redirect-заметкой (прецедент: `ARCHITECTURE.md`).
- Нехватка данных: `TBD` (не определено), `ASSUMPTION` (допущение до ответа заказчика), `NEEDS REVIEW` (спорно/устарело). Утверждённое заказчиком — снимать маркер и повышать статус.

## 8. Создание новых разделов

1. Следующий свободный номер: DOC-030+ (нумерация сквозная, без дыр и переиспользования).
2. Создать файл по формату раздела 3; назначение — не дублирует существующие (проверить DOC-MAP).
3. Обновить: `DOCUMENTATION_MAP.md` (дерево, таблица, группа) и `documentation.manifest.json`; при новом домене — таблицу источников истины в INDEX.md.
4. Гайды пользователя (21–24) и внутренние разделы не смешивать: аудитория в паспорте обязательна.

## 9. Ответы на вопросы людей

- Отвечать по документации; указывать ID раздела-основания (`согласно DOC-014 §5`).
- Вопрос без ответа в документации: честно сказать «не определено»; предложить TBD-внесение; не выдумывать поведение.
- Конфликт документов — это бага: исправить источник и сообщить об исправлении в ответе.

## Чек-лист ИИ-агента перед завершением правки

- [ ] Изменён документ-источник, а не копия?
- [ ] Паспорт актуален (summary, when_to_read, keywords)?
- [ ] Манифест обновлён (status, last_updated)?
- [ ] Связанные документы и ссылки согласованы?
- [ ] Новых TBD/ASSUMPTION меньше, чем снятых (или обоснованы)?
- [ ] Не введено нарушение запретов раздела 2.5?
