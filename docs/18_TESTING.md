# Тестирование

## Краткое содержание

- Пирамида тестов.
- Обязательные e2e-сценарии.
- Тестирование AI (fake-провайдер, eval-наборы).
- Нагрузочные тесты.
- CI.

## 1. Пирамида

| Уровень | Область | Инструменты | Требование покрытия |
|---|---|---|---|
| Unit | `packages/core`: state machine диалога, RulesEngine, prompt-builder, retrieval-фьюжн (RRF), валидатор structured output | Vitest | ≥ 80% ядра |
| Integration | модули api + реальная БД: миграции, seq-выдача, каскады chunks, изоляция project_id | Vitest + Testcontainers (pgvector, redis) | все репозитории/сервисы данных |
| E2E API | сценарии виджет+оператор против поднятого стека | Vitest supertest / scenarios | список раздела 2 |
| Build checks | widget-бандл ≤ 60 КБ gzip; типы shared не сломаны | CI-шаг | падение сборки при нарушении |
| Eval AI | качество ответов на golden set | прогон из админки; CI-автоматизация V2 | TBD пороги |

Fake-провайдер LLM (детерминированные ответы, эмуляция стрима/ошибок/таймаутов) — обязателен для любых тестов, где участвует AI; реальные вызовы провайдера в CI не выполняются.

## 2. Обязательные e2e-сценарии

| # | Сценарий | Проверяет |
|---|---|---|
| E1 | init → сообщение → стриминг → финальное сообщение с цитатами | Conversation Engine, seq, события |
| E2 | Retrieval-гейт: вопрос вне KB → fallback, LLM не вызывается | гейт, экономия |
| E3 | «Позовите менеджера» → handoff → оператор принял → ответ оператора | state machine, очередь |
| E4 | low_confidence → авто-эскалация по правилу | RulesEngine |
| E5 | Reconnect: пропущенные сообщения добираются after_seq | кэтч-ап, порядок |
| E6 | Возврат чата AI оператором → AI отвечает с контекстом | переходы, история |
| E7 | Офлайн: нет операторов → email-заявка | lead capture |
| E8 | Изоляция: visitor A не читает диалоги visitor B; оператор проекта X не видит проект Y | безопасность |
| E9 | Переиндексация документа: version+1, swap, старые вектора удалены | пайплайн KB |
| E10 | Rate limit на сообщения виджета | 429 + retry_after_s |

## 3. Тестирование AI

- **Юнит:** prompt-builder — снапшоты промптов (изменение промпта = осознанный коммит); валидатор схем.
- **Eval-набор проекта:** вопросы → эталонные ответы/источники; метрики hit@k, точность цитат, доля эскалаций, латентность (DOC-011 §8).
- **Регрессии промптов** (автоматизация в CI) — V2.

## 4. Нагрузочные тесты

Цель MVP-профиля (NFR-7): ~50 одновременных диалогов, стриминг включён.

- Инструмент: k6 (или TBD) против тестового стенда с fake-провайдером.
- Метрики: латентность первого токена ≤ 3 с (P95), отсутствие утечек памяти api при 1-часовом прогоне, глубина очереди worker при массовой загрузке документов.

## 5. CI-конвейер

```text
PR / push:
  lint + typecheck (все пакеты)
  unit (core, shared)
  build (включая проверку размера widget)
  smoke: бутстрап AppModule без БД (`node dist/main.js` → /health 200)
  integration + e2e: GitHub Actions service postgres (pgvector:pg16)
release (тег):
  сборка Docker-образа chat-platform:<semver>
  прогон restore-теста бэкапа на чистой ВМ (раз в релиз, TBD)
```

Smoke-бутстрап обязателен: typecheck и юниты DI-граф Nest не проверяют (дефект Ф3–Ф4 — IR-039 в DOC-031); шаг вводится в CI — до того см. D-13.

> Факт по итогам аудита IR-059: Testcontainers не используется — e2e идут
> против service-контейнера postgres в ci.yml; release-пайплайн (сборка образа
> по тегу + restore-тест) отсутствует — образ собирается только install.sh на
> VPS (D-17). Пункт «Testcontainers» в схеме выше — целевое состояние.

## Локальный запуск e2e на демо-стенде (PGlite)

Демо-БД (`demo/db-server.mjs`, PGlite/WASM + pgvector по wire-протоколу) — не
production-grade сервер: при длительной многофайловой нагрузке wire-сервер
деградирует (ECONNRESET / «unexpected parseComplete», соединения не
освобождаются до рестарта). Проверено в реаудите RA-I-6/RA-API-10.

Правила локального прогона:
- файлы фаз запускать ПО ОДНОМУ: `npx vitest run src/e2e/phase3.e2e.ts --no-file-parallelism`;
- при первых ECONNRESET — перезапустить db-server (SIGTERM теперь закрывает БД корректно);
- долгоживущий API (:3000) держит пул соединений — перед прогоном e2e его стоит остановить;
- CI от этих проблем свободен: там настоящий Postgres 16 из service-контейнера.

## Частые ошибки

- **Реальные вызовы LLM в CI** — деньги и нестабильность; только fake-провайдер.
- **Тесты без Testcontainers (мок БД)** — seq/HNSW/каскады не проверяются реально.
- **Отсутствие теста на изоляцию арендаторов** при добавлении новых запросов к доменным таблицам.
