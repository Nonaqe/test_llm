## 3. MAJOR по темам

### Аутентификация/сессии
- Reuse-detection refresh не отзывает семейство сессий (только 401): украденный токен живёт весь TTL; нет logout-all и отзыва при смене пароля (`auth.service.ts:93`)
- CSRF double-submit из docs/15 §3 не реализован нигде; единственный слой — SameSite=Lax (`app-setup.ts`)
- `trust proxy` не настроен, TRUST_PROXY из docs/17 не читается: за Caddy req.ip = IP прокси → init-лимит 30/мин становится ОДНИМ на всех посетителей (массовые 429), brute-force ключ вырожден, аудит пишет IP прокси
- SETUP_TOKEN: сравнение `!==` (не constant-time), роут без throttle, проверка count()>0 вне транзакции (TOCTOU → два owner'а)
- Cookie `secure` привязан к NODE_ENV=production: self-hosted за TLS с NODE_ENV≠production шлёт куки без Secure
- Bearer-доступ наравне с cookie ослабляет httpOnly-модель (реплей украденного токена вне браузера)

### SSRF (дополнение к H2)
- TOCTOU/DNS-rebinding: проверка резолвит имя сама, fetch резолвит снова (`ssrf.ts:72`)
- Порт не ограничен 80/443 → сканирование произвольных TCP-портов публичных хостов

### Надёжность бэкенда
- Idempotency-кэш виджета: ключ только Idempotency-Key → межарендовая коллизия (чужое сообщение из кэша), check-then-set без блокировки, Map чистится никогда (`widget.service.ts:190`)
- `void this.engine.onVisitorMessage(...)` без .catch: падения до runLlm = unhandled rejection + молчаливая потеря хода (`widget.service.ts:224`)
- knowledge: голый `Error("NOT_FOUND")` → 500 вместо 404; reindex глотает ошибки `.catch(()=>undefined)` навсегда pending; uploadDocument заворачивает ЛЮБУЮ ошибку в 422; replaceForFaq удаляет чанки до вставки новых вне транзакции (FAQ выпадает из поиска при сбое); UPLOADS_DIR ≠ UPLOAD_DIR из env-схемы
- Дубли email (users/setup insert) → PG 23505 → 500 вместо 409
- inbox accept/returnToAi/close — multi-step записи без транзакции
- fallback_streak: чтение-изменение-запись без атомарного инкремента (`conversation-engine.service.ts:215`)
